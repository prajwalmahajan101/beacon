# M1.2 journal — bounded buffer + non-blocking emit + drop policy

**Branch:** `feature/m1.2-bounded-buffer` off `main@293e904`
**Goal:** un-disable C2 (`<1ms` p99 emit) + C3 (`DROP_OLDEST` policy under overflow)
**Plan:** `~/.claude/plans/refactored-knitting-walrus.md`

## What I did

- Ratified `ArrayBlockingQueue<LogRecord>` as the bounded store (FIFO, wait-free `offer()`).
- Picked `DROP_OLDEST` as the default policy; `DROP_NEWEST` as the alternative; `SPILL_FALLBACK` left to throw `UnsupportedOperationException("M1.4")` until the fallback sink lands.
- Added `BeaconConfig.withBufferCapacity` + `.withDropPolicy` helpers (avoided a full Builder — premature before YAML loader).
- Decided `emit()` is `void`; drop count surfaces via `metrics.dropped()` instead of a return value.
- Kept `Enricher` and `Redactor` stubbed; emit goes record → buffer directly (M1.6 inserts the pipeline).

## Problems I faced

Zero significant ones — plan executed clean. The 8×2k concurrent `DROP_OLDEST` test surfaced no flakes; atomic counter accounting was right on first run.

The only friction was working out how to phrase the scope note in C2/C3 bodies — `scenarios.yaml` references `exporter: blocking`/`stalled` parameters that aren't testable until M1.4. Solved by adding an explicit inline comment in each test method calling out what's deferred and what's testable now.

## What could have been done better

Nothing substantive. M1.2 is in-memory data structures; the spec gave clean acceptance criteria; tests caught what they needed to. If I'd known M1.5 would force `BeaconSdkEmitTest` to revise twice more, I might have split the buffer-state assertions out of the SDK-level test from the start.

## Changes carried back to earlier phases

None. M1.0/M1.1 untouched.

## What's next

- **Hand-off to M1.3** — batch flusher needs `BoundedBuffer.drainTo` (already exposed) and a `poll(timeoutMs)` to avoid busy-waiting. The flusher will auto-start in the SDK constructor; `BeaconSdkEmitTest` will need to stop it to keep observing pure buffer state.
- **v2 carry-list** — `ArrayBlockingQueue`'s known contention at very high producer counts; capacity is fixed at construction; per-record `Object[]` allocation up-front at full capacity (80 KB for default `10_000`). All acceptable for v1.
