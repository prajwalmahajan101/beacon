# M3.1 journal — DLQ + idempotency + composite partition key

**Branch:** `feature/ingest-dlq-idempotency` off `main@1aacfce`
**Goal:** Harden the Kafka→ES indexer path with composite partition key, DLQ routing for poison records, offset-commit-after-write, restart resilience, hot-partition detection, DLQ replay tooling, and platform telemetry. Seven INGEST requirements (05, 06, 07, 08, 13, 14, 17). One combined ADR-0026.
**Plan:** `.claude/plans/generic-leaping-newell.md` (5 waves, approved 2026-10-31).

## What I did

- **Wave 1 — Composite partition key** (`ca474cc`): Changed `LogRecordProducer` from `send(topic, value)` (null key, round-robin) to `send(topic, key, value)` with a `KeyedRecord` record type. `IngestService.partitionKey()` computes `service.name|trace_id` from the mapped `LogRecord` — no JSON re-parsing. Kafka `KAFKA_NUM_PARTITIONS=8` in docker-compose. Tests: `partitionKeyUsesServiceNameAndTraceId` unit test + `sameKeysLandOnSamePartition` IT.

- **Wave 2 — DLQ routing** (`a7a5d24` RED, `bd70dbb` GREEN): Switched Vector's Kafka source from `codec: json` (silent drop on decode failure) to `codec: bytes` + a `remap` transform that tries `parse_json`. Valid records → `es_out` (clean M0 JSON, Kafka metadata stripped). Poison records → dual sink: `dlq_kafka` (`beacon.logs.dlq` topic) + `dlq_es` (`beacon-logs-rejected` ES index) with `raw_message`, `error`, `dlq_reason` fields. Enabled `acknowledgements.enabled: true` on ES sink. Manually verified: non-JSON lands in both DLQ targets, valid records clean in `beacon-logs`.

- **Wave 3 — Restart resilience** (`28462e6`): Three E2E tests — restart Vector, gateway, and ES mid-stream, assert no acknowledged records lost. All passed without additional config (Wave 2's ack setting was sufficient). `_restart_service` helper polls `docker compose ps --format` for health.

- **Wave 4 — Scripts + telemetry** (`4ab847d` RED, `8b65b38` GREEN): `scripts/check-partition-skew.sh` (INGEST-06) — `kafka-consumer-groups.sh --describe` + max/avg lag ratio. `scripts/replay-dlq.sh` (INGEST-14) — console consumer/producer pipe. `IngestService`: `ingest.duration` Micrometer Timer wrapping the ingest method (completes RED metrics). Vector: `internal_metrics` source enabled.

- **Wave 5 — Docs** (this commit): ADR-0026, CHANGELOG, this journal, roadmap updates.

## Problems I faced

- **Vector `log_namespace: true` + `codec: bytes` puts raw data at root, not `.message`.** The `remap` transform's `string!(.message)` failed with "expected string, got null". Fix: removed `log_namespace: true` so raw bytes land in `.message` per the default namespace. Valid records still index clean because `remap` replaces the entire event with the parsed JSON (`. = parsed`), stripping Kafka metadata fields.

- **Shared Kafka topic in ITs caused test bleed.** `sameKeysLandOnSamePartition` picked up records from the previous test (`producesKeyedRecordReadBackByAConsumer`) because both searched for `"body":"hello"` on the same singleton topic. Fix: unique body markers per test.

- **TDD red-green discipline.** Waves 2-4 followed TDD: failing tests committed first, then implementation. Wave 1 was implementation-first (corrected for subsequent waves). The `ingest.duration` timer test confirmed RED (failed before Timer wiring) and GREEN (passed after).

## What could have been done better

- Should have checked Vector's `log_namespace` interaction with `codec: bytes` before writing the remap transform — a 2-minute `docker compose logs vector` check would have caught the `.message` null immediately.
- Wave 1 should have been TDD from the start (tests before code). The discipline was adopted for Waves 2-4 and should carry forward.

## Changes carried back to earlier phases

- `docker-compose.yml` (M3.0a artifact): added `KAFKA_NUM_PARTITIONS: 8` for the composite partition key.
- `deploy/vector/vector.yaml` (M3.0c artifact): replaced the `codec: json` source with `codec: bytes` + remap/filter transforms + DLQ sinks. The original skeleton pipeline is fully superseded.

## What's next

- **M3.2 (Multi-tenancy):** API-key auth → tenant scope (`X-Scope-OrgID`), per-tenant rate limiting (429 + `Retry-After`), attribute key rejection. Gateway-side changes, no Vector/ES config.
- **M3.3 (ES storage layout):** Index template (`flattened` attributes, `total_fields` cap), data streams, ILM. This is when the DLQ error taxonomy becomes load-bearing — `dynamic: strict` will produce real 4xx ES rejections.
- **Carry-forward:** The `dlq_es` sink writes rejected records to a plain auto-mapped index. M3.3 should add an explicit mapping template for `beacon-logs-rejected` alongside the main index template.
