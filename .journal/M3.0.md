## Problems I faced

- **Vector's healthcheck was silently broken — caught only at the human-verify gate.** The plan (following RESEARCH Pitfall 5) specified a `wget -qO- http://localhost:8686/health` healthcheck and justified the `-debian` variant as "has a shell for wget." On the first real `docker compose up -d --wait`, ES and Kafka went healthy but **Vector hung `unhealthy`** and `up --wait` exited non-zero — even though `curl http://localhost:8686/health` from the *host* returned `{"ok":true}`. The image itself was fine; the *in-container probe* was the problem. Diagnosis: `docker run --rm --entrypoint sh timberio/vector:0.41.1-debian -c 'command -v wget curl busybox'` → **all three absent**. `0.41.1-debian` ships neither wget, curl, nor busybox. It *does* ship `bash` and the `vector` binary. Fix: probe `/health` over bash's `/dev/tcp` (`exec 3<>/dev/tcp/localhost/8686; printf 'GET /health ...'; grep -q '200 OK'`), invoked via `["CMD","bash","-c",...]` because the default `CMD-SHELL` is dash (no `/dev/tcp`). Validated against a throwaway container *before* committing, then re-ran the full stack green. The RESEARCH assumption was simply wrong for this tag — recorded the correction in the ADR and CHANGELOG so it doesn't get re-copied into 5.2.
- **YAML/shell quoting for the `/dev/tcp` probe.** Getting `printf` CR/LF escapes and the grep pattern through a JSON-flow-in-YAML string without dash mangling them took a couple of iterations; landed on `grep -q '200 OK'` (matches the `HTTP/1.1 200 OK` status line) to avoid escaping the JSON-body double-quotes entirely.

## What could have been done better

- **The healthcheck should have been validated at authoring time, not deferred to the human gate.** A 10-second `docker run ... command -v wget` during Task 2 would have caught the missing-binary problem before it ever reached the checkpoint. Lesson: when a healthcheck depends on a tool being *inside* an image, prove the tool exists in that exact tag rather than trusting a "the debian variant has a shell" research note — "has a shell" ≠ "has wget."
- **RESEARCH carried an unverified tertiary claim (Pitfall 5) as fact.** Worth tagging research pitfalls with a confidence/verification marker so downstream plans know which ones are load-bearing-but-unchecked.
