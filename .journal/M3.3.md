## Problems I faced

- **VRL compiler E651 (unnecessary error coalescing).** `.kafka_headers."X-Scope-OrgID" ?? null` rejected by Vector's VRL compiler — field access on an object returns null for missing keys (can't fail), so `??` is redundant. Fix: remove the `??` operator. Vector exited 78 (config error) and all 5 Java E2E tests failed before the fix.

- **M3.2 headers_key revert root cause.** The original M3.2 attempt added `headers_key: "kafka_headers"` + extracted tenant_id in the remap. The revert said "Vector adds kafka_headers to the event even when no headers are present." The actual fix: capture the header value in a local VRL variable BEFORE `. = parsed` replaces the entire event. After overwrite, `kafka_headers` is gone — no stray fields reach ES's `dynamic: strict`.

- **Data streams require `@timestamp`.** The M0 canonical JSON has `timestamp`, not `@timestamp`. Discovered during manual testing — data stream write failed silently (Vector retried). Fixed by stamping `."@timestamp" = .timestamp` in the `parse_json` remap.

## What could have been done better

- The `@timestamp` requirement for data streams should have been caught during planning, not manual testing. A quick ES data stream docs read would have flagged it.
- The VRL `??` syntax could have been tested with `vector validate` before a full E2E run.
