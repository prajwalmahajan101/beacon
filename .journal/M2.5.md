## Problems I faced

- **The dotted-key-is-flat subtlety.** C10's `redact_keys: [password, card.number]` provides `card.number` as a flat attribute key — NOT a nested `{card: {number: …}}` path. The temptation is to "helpfully" split a dotted key into a path walk, but Java doesn't (ADR-0007's walker matches literal keys at each node), so the Python redactor must compare `card.number` VERBATIM as one key string. Confirmed by writing `test_dotted_key_is_flat_not_nested_path` both ways: a nested `{card:{number:'x'}}` under key `{card.number}` is LEFT UNCHANGED (identity preserved), and a literal `{card.number:'x'}` IS redacted. Getting this wrong would have masked a `number` sub-key the scenario never asked to redact.
- **The redactor fail-safe: raise-with-original vs return-partial.** On a deadline/over-depth trip, a partially-walked record could contain SOME redacted values and SOME un-walked (still-PII) values. Returning that partial record would leak PII to the wire — exactly the failure the whole ReDoS guard exists to prevent. So the Redactor RAISES (`RedactorTimeoutError` carrying the ORIGINAL, untouched record) rather than returning a partial; the caller routes the original to the fallback sink (never the OTLP wire). This mirrors Java ADR-0007 #8. The `_DeadlineExceeded` sentinel is the mechanism — it unwinds the whole recursion in one throw so no partial output ever escapes.
- **Why `MappingProxyType` and not a plain dict in the `ContextVar`.** `contextvars` copy-on-spawn copies the `Context` at `asyncio.Task` creation, but the copy is SHALLOW — each Task's slot points at the SAME map object the parent holds. A mutable `dict` there would let a child Task (or any holder of the `get_context()` reference) mutate a `trace_id` a sibling Task reads — a silent cross-task race. Freezing each snapshot as `MappingProxyType` + making `update_context` copy-on-write makes the shared-by-reference sharing harmless. `test_async_child_update_does_not_leak_to_parent` proves the isolation.
- **Driving async tests without `pytest-asyncio`.** The suite has no `pytest-asyncio` and I did not want to add a dev dependency just for two tests. Solution: keep the tests plain SYNC test functions that call `asyncio.run(_coro())` internally — `asyncio.run` creates the loop, runs the coroutine (which spawns the child Task, exercising copy-on-spawn), and tears the loop down. `uv.lock`/`pyproject.toml` stayed untouched (checked). Plan 03's C11 across-async sub-case uses the same `asyncio.run` idiom in the frozen conformance dir.
- **`format_trace_id`/`format_span_id` vs hand-`%032x`.** The OTel-Python helpers already render canonical lowercase zero-padded hex (32/16), so the Span-primary path uses them directly — no hand-formatting, no divergence risk from Java's rendering. Only the ContextVar-fallback path needs an explicit `.lower()` (a mixed-case env value must still yield a schema-valid lowercase id) + a `_is_valid_hex` guard (garbage refused; an invalid `span_id` alongside a valid `trace_id` is omitted, never fabricated).
- **The two Wave-1 plans both edited `pipeline/__init__.py`.** Plan 01 (redactor) and Plan 02 (enricher) ran in parallel and both add an export line to `beacon/pipeline/__init__.py`. Plan 02 committed `Enricher` first (`99b5594`); Plan 01's `Redactor`/`RedactorTimeoutError` export MERGED alongside it rather than overwriting. The final `__all__` is the correct additive union `["BoundedBuffer", "BatchFlusher", "BatchSink", "NOOP", "Enricher", "Redactor", "RedactorTimeoutError"]` — exactly the additive resolution the plans' file-ownership note anticipated; neither export was dropped.

## What could have been done better

- **Body-string scrubbing was deferred (again).** Both Java (ADR-0007 #5) and Python (ADR-0018 #5) leave a `str` body opaque — structured PII inside a JSON-shaped body string is not scrubbed. The Redactor even has a defensive `isinstance(body, Mapping)` branch that is unreachable in v1 (body is typed `str`). It is the right call for the emit-path budget, but a future reader should not mistake the defensive branch for a live feature; the ADR documents it as forecast for a `scan_body` opt-in.
- **Whether a thread-boundary context wrapper is worth it now.** ADR-0019 documents that only `asyncio.Task` copy-on-spawn is automatic — a bare `threading.Thread` / `ProcessPoolExecutor` does NOT inherit `ContextVars`. That is the correct scope for M2.5 (the contract only requires `across_async`), but a host app that emits from a thread pool will silently see the empty fallback map. A `contextvars`-aware executor wrapper (the real Python analogue of `BeaconExecutors`) is deferred; if a real workload surfaces it, M2.6+ adds it. Flagged so the deferral is deliberate, not an oversight.
- **Whether `RedactorConfig` should fold into a future unified `BeaconConfig`.** M2 has grown a fleet of per-stage config carriers (`BufferConfig`, `FlusherConfig`, `ExporterConfig`, now `RedactorConfig`). Each is clean in isolation, but the M2.6 `emit()` assembly will want a single layered `BeaconConfig` (env > sysprop > builder) like Java's. Consolidating now would be premature — the carriers are correct and the loader is later-M2 growth — but the eventual unification is a known refactor.

## Journal

Wave 1 ran the redactor (Plan 01) and the enricher+context (Plan 02) in parallel, and the two never really collided except at `pipeline/__init__.py` — where the additive-union resolution the plans anticipated held: Plan 02 committed `Enricher` first, Plan 01's `Redactor` merged alongside, and the final `__all__` carries both. The redactor's whole art was the `_DeadlineExceeded` sentinel + identity preservation: the sentinel means no partial output can ever escape a timeout (it unwinds the recursion in one throw, `redact` catches it and re-raises the public error with the ORIGINAL record), and the identity preservation means the common no-PII path is allocation-free (`out is rec`). The dotted-key-is-flat test was the one I most wanted green early — it is the exact C10 subtlety and the easiest place to be "clever" and wrong.

Plan 02's load-bearing realization was that Python is *simpler* than Java here: `asyncio.Task` copy-on-spawn carries the `ContextVar` map across an async boundary for free, so there is no `BeaconExecutors` to write. The whole ADR-0008 machinery (four `wrap(...)` factories, per-task MDC snapshots) collapses to "set a `ContextVar`, spawn a Task, it's there." The catch is that copy-on-spawn is SHALLOW — the map is shared by reference — so freezing each snapshot as `MappingProxyType` + copy-on-write `update_context` is what makes it race-free. The two async tests (inherit + no-leak-back) driven via `asyncio.run()` from sync bodies kept `pytest-asyncio` out of the dep tree.
