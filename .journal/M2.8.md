## Problems I faced

- **The real latent bug `mypy --strict` caught.** `_shutdown.py` passed `ExporterConfig.endpoint` (typed `str | None`) into `OtlpExporter.__init__(endpoint: str)`. The strict type gate flagged the `arg-type` mismatch on its first run. The honest fix was NOT a cast or ignore — the RUNTIME contract genuinely accepts `endpoint=None` (`build_pipeline` passes `None` → OTel resolves its own default target → fail-fast export → `ResilientSink` fallback). So I widened `OtlpExporter`'s ctor param AND the `endpoint` property to `str | None` so the signature tells the truth. This is the day-one proof that a strict type gate pays for itself (Pitfall #30).
- **The OTel typing boundary.** The OTel SDK ships only partial `py.typed` for the internal `_logs` / exporter modules Beacon imports, so `mypy --strict` couldn't resolve them. Rather than sprinkling `# type: ignore` at each call site, I used a single config-level `[[tool.mypy.overrides]] opentelemetry.* ignore_missing_imports = true` — one honest boundary declaration. `yaml` got a proper stub (`types-PyYAML`) instead, since one exists.
- **Coverage artifacts leaking into the working tree.** Running the CI pytest-cov command locally produced `.coverage` + `coverage.xml` untracked. Added them (+ `htmlcov/`) to `beacon-sdk-python/.gitignore` so the report-only artifacts get uploaded, never committed.

## Journal

- Wave ordering is the whole trick: a PR that adds a gate must pass that gate. Cleaning the tree in Waves 1–2 and flipping the gates in Wave 3 means the gate-adding PR is green on its first run — no "add the gate, watch it fail, then fix" thrash. This is the Python replay of Java CI-01's reformat-before-gate discipline, and it worked cleanly.
- The single most valuable thing `mypy --strict` did was find a bug, not enforce style. The `endpoint: str | None` widening is the kind of latent type lie that survives every test (because the runtime genuinely handles `None`) but is exactly the class of defect a strict type gate exists to catch. If the floor only ever did that once, it paid for itself.
- Restraint was a deliberate design goal, not laziness: no darglint, no standalone pydocstyle, no black, no coverage threshold, no OS/Python matrix. Every one of those is a defensible future addition — but adding them now would be CI completionism (Pitfall #22) delaying M2.9. ADR-0021 names each skip with its condition-for-adoption so the next contributor doesn't relitigate.
- CI-PY-03 (mypy) has no Java sibling — a small but real asymmetry. Java's `javac` type-checks at compile, so its floor never needed a standalone type gate; Python's optional typing makes one a genuine Python-specific addition. Worth recording so the "why does Python have one more gate" question has an answer.
